# privy_stream — десктопный клиент

Tauri 2 + Vite + React 19 + TypeScript. Дизайн — по `../Privy Stream.dc.html` и `../README.md` (хэндофф).

## Запуск

```sh
npm install
npm run dev          # только фронтенд в браузере: http://localhost:1420
npm run tauri dev    # нативное окно (нужен Rust: https://rustup.rs)
npm run tauri build  # релизная сборка .app/.dmg/.msi
```

Список узлов при первом запуске пуст. Узел добавляется по адресу `host:port`
(или со схемой: `https://node.example`). Без схемы `localhost`, `*.local` и приватные
IP идут по http, остальные — по https.

Все адреса, кроме демо-узлов из макета, работают через HTTP-клиент по контракту
`privy_stream/api/v1/openapi.yaml`. Локальный gateway из docker-compose — `localhost:8080`.
Демо-адреса обслуживает мок: `eu3.privy.stream:8443`, `ind.local:9000`,
`89.211.4.77:8443` (у них есть полка) и `192.168.1.14:8443` (не отвечает).

## Два режима

Код один, режим выбирается при запуске:

| | Приложение (Tauri) | Веб-версия (браузер) |
|---|---|---|
| Узлы | любое число, добавляются по адресу | один, из `config.json`, сменить нельзя |
| Список узлов | `~/Library/Application Support/stream.privy.client/nodes.json` | не хранится, каждый раз из конфига |
| Токены | системный keychain | localStorage (защищён строгим CSP) |
| Библиотека | есть | нет (у браузера нет локального диска) |

Для разработки режим можно переопределить: `VITE_CLIENT_MODE=app npm run dev`. Веб-режиму
без контейнера узел задаётся так: `VITE_WEB_NODE_URL=http://localhost:8080 npm run dev`.

## Веб-версия в Docker

Отдельный контейнер (nginx + статика), с бэкендом не связан — можно ставить на любой сервер:

```sh
cp .env.example .env        # указать PRIVY_NODE_URL
docker compose up -d --build
```

| Переменная | Что это |
|---|---|
| `PRIVY_NODE_URL` | адрес узла: `https://node.example` или `https://example.com/api` (обязательно) |
| `PRIVY_NODE_NAME` | имя узла в интерфейсе, по умолчанию — домен |
| `PRIVY_WEB_PORT` | порт на хосте, по умолчанию 8081 |

При старте контейнер пишет `config.json` и CSP из этих переменных (`docker/40-privy-config.sh`).
CSP разрешает странице ходить только на этот узел. Без `PRIVY_NODE_URL` приложение показывает
экран «веб-версия не настроена». Проверка живости — `GET /healthz`.

Контейнер отдаёт plain HTTP на порту 80. TLS — на обратном прокси перед ним (Caddy, Traefik, nginx).
Если веб-версия открыта по https, узел тоже должен быть по https: браузер не пустит страницу
с https на `http://`-адрес. Домен веб-версии нужно добавить в `CORS_ALLOWED_ORIGINS` в `.env` бэкенда (десктопный клиент разрешён всегда).

## API узла (v1)

`src/api/http.ts` — только пользовательские эндпоинты:

| Эндпоинт | Где используется |
|---|---|
| `POST /login`, `/register` | экран входа |
| `POST /refresh` | автоматически при 401; параллельные запросы делят один refresh |
| `POST /logout` | кнопка «ВЫХОД» |
| `GET /catalog/tracks/search`, `/catalog/artists/search` | каталог (поиск) |
| `GET /catalog/albums/{id}`, `/albums/{id}/tracks` | страница релиза |
| `GET /catalog/artists/{id}`, `/albums`, `/tracks` | страница артиста |
| `GET /stream/{id}` | плеер |
| `POST /catalog/tracks/{id}/listened` | засчитать прослушивание, см. ниже |
| `GET /catalog/tracks/search` без токена | handshake: любой ответ = узел жив |

**Прослушивания** (`src/layout/listenReporter.ts`). Клиент копит реально проигранное
время: перемотка и пауза не считаются. На 30-й секунде (для треков короче минуты — на
половине длительности) отправляет `POST …/listened` один раз за проигрывание. Без повторов
и без очереди при оффлайне. Узлы, где эндпоинта ещё нет (404/405), молча пропускаются.
Эндпоинт пока не реализован в gateway.

Админские POST (добавление артистов, альбомов, треков, загрузка файлов) не подключены.
`GET /catalog/tracks/{id}` и `/exists` клиенту пока не нужны: путь к файлу UI не показывает.

Ограничения API v1, которые видны в интерфейсе:
- нет списка релизов узла — каталог работает только через поиск;
- у альбома нет года, жанра, формата, кода; у артиста нет статистики — эти поля скрываются;
- нет дескриптора узла — имя узла берётся из адреса, владелец и тип доступа неизвестны;
- стрим идёт по короткоживущему токену из `POST /stream/token` в query `<audio src>`
  (`?access_token=…`, TTL ~10 минут): файл тянется Range-запросами по мере игры.
  Узлы старой прошивки без этого эндпоинта стримить не умеют.

## Структура

```
src/
  api/          типы NodeApi, мок-узел, хуки TanStack Query (ключи [host, ресурс])
  platform/     токены: keychain через Tauri, в браузере — память процесса
  store/        Zustand: узлы, сессия, плеер, настройки
  styles/       дизайн-токены (CSS-переменные) и глобальные стили
  ui/           примитивы: Button, Field, Cover, StatusDot, TrackTable…
  layout/       шапка, сайдбар, нижний и полноэкранный плеер, AudioEngine
  screens/      Auth, Servers, Catalog, Album, Artist, Library, Settings
src-tauri/      Rust: окно, CSP, команды tokens_get/set/delete (crate keyring)
```

## Что сделано иначе, чем в макете (по хэндоффу)

- Нет переключателя DESKTOP/MOBILE: мобильный вид включается сам при ширине экрана до 720px
  (`src/lib/useMobile.ts`, `@media (max-width: 720px)` в CSS-модулях). Вместо сайдбара — таб-бар
  ПОЛКА / УЗЛЫ / ФОНОТЕКА / Я, вместо нижней панели — мини-плеер; экраны перестраиваются в одну колонку.
  Окно Tauri не уже 1100px, так что мобильный вид работает только в браузере.
- Плотность — в «Настройках», а не в шапке. Реализована CSS-переменными (`data-density` на `<html>`).
- Сайдбар: Серверы, Каталог, Библиотека, Настройки. Артист и релиз открываются из каталога.
- Демо-таймер заменён на `AudioEngine`: трек со `streamUrl` играет через `<audio>`,
  у мок-треков потока нет, поэтому позиция идёт по часам.
- Длительность релиза и склонения («2 трека») считаются, а не зашиты.
- Добавлены состояния: скелетоны, ошибки запросов к узлу, пустой треклист.
- На экране входа можно добавить узел по адресу (чип «+ ДОБАВИТЬ УЗЕЛ»): без узла
  регистрироваться негде. При пустом списке форма добавления открыта сразу.
