# Handoff: privy_stream — десктопный клиент музыкального стриминга

## Overview

privy_stream — федеративный музыкальный стриминг. Единого сервера нет: любой поднимает свой узел (node), заливает туда фонотеку и раздаёт адрес; клиент подключается к узлу и слушает/ищет музыку только на нём. Позиционирование — прослушивание без региональных блокировок и внешних списков запрещённого, приватность по умолчанию (история не пишется, телеметрии нет).

Задача: реализовать **десктопное приложение** (первая цель) по приложенному макету. Рекомендуемый стек — **Tauri + Vite + React + TypeScript** (нативный webview, бинарь ~10 МБ, Rust-сторона нужна для keychain-хранения токенов по узлам, дискового кэша аудио и кастомного протокола для стрима в обход CORS). Electron — только если понадобятся node-модули в рантайме.

Бэкенд пишет сам заказчик (Go: user_service — auth c JWT RS256 — готов, gateway в работе). Клиент должен быть «пустым»: список узлов и ключи живут локально, baseURL подставляется из выбранного узла.

## About the Design Files

Файл `Privy Stream.dc.html` в этом бандле — **дизайн-референс, сделанный в HTML**. Это прототип, показывающий внешний вид и поведение, а не продакшн-код для копирования. Задача — **воссоздать этот дизайн в целевом окружении** по его правилам (компоненты, роутинг, стили, менеджер состояния), а не встраивать HTML как есть.

Технически файл — компонент со шаблоном и классом логики: разметка эквивалентна JSX (атрибуты уже camelCase, `style="…"` компилируется в объект стилей), `<sc-for list as>` = `.map()`, `<sc-if value>` = условный рендер, `{{ x }}` = значение из `renderVals()`. Класс логики — это React class component без `render()`: `state`, `setState`, `componentDidMount`. Перенос в `.tsx` механический; `renderVals()` переносится почти дословно (или раскладывается на хуки/селекторы).

Открыть макет: `Privy Stream.dc.html` и `support.js` должны лежать рядом, открывать через локальный сервер (`npx serve .`), не по `file://`.

## Fidelity

**High-fidelity.** Цвета, типографика, отступы, размеры и состояния — финальные, воссоздавать точно. Все значения перечислены ниже в Design Tokens. Обложки и фото артистов — плейсхолдеры (диагональная штриховка с подписью и указанием размера); в приложении на их месте реальные изображения с узла, плейсхолдер остаётся как состояние загрузки/отсутствия арта.

|---|---|---|---|---|---|---|---|

**Поведение:**
- Клик по строке/кнопке online-узла → статус `ПОДКЛЮЧЕНИЕ…` с мигающей точкой, через ~650 мс подключение: активным становится новый узел, приложение уходит на Catalog, поиск и фильтр сбрасываются. В приложении заменить таймаут реальным запросом к узлу (handshake + получение дескриптора), сохранив промежуточное состояние.
- Клик по offline-узлу → ошибка `503 · {host} не отвечает`, подключение не происходит.
- Добавление узла: адрес валидируется по `^[\w.\-]+(:\d+)?$`, иначе `400 · адрес вида host:port, например 10.0.0.5:8443`; дубликат по host → `узел уже в списке`. Новый узел появляется в списке со статусом online, ping 20–80, тип доступа `неизвестно`, описание «узел добавлен вручную, метаданные ещё не получены», владелец «добавлен тобой». В приложении: пробить узел запросом, взять имя/владельца/тип доступа из его дескриптора, реальный ping измерить.

## Interactions & Behavior

**Навигация:** сайдбар и крошки; Catalog → Album (клик по карточке), Album → Artist (клик по имени), Artist → Album (клик по релизу в дискографии), `← КАТАЛОГ` / `← НАЗАД` — возврат в каталог. Чип узла в шапке, строка «СМЕНИТЬ УЗЕЛ» в сайдбаре и кнопка из пустого состояния ведут на Servers.

**Смена узла:** промежуточное состояние «ПОДКЛЮЧЕНИЕ…» (мигающая точка) → успех: активный узел меняется, приложение уходит на Catalog, поиск и фильтры сбрасываются, каталог и поиск скоупятся по новому узлу (заголовок, счётчик релизов, мобильная полка). Локальная фонотека и очередь воспроизведения не сбрасываются. Ошибка подключения — инлайн-сообщение на экране Servers, активный узел остаётся прежним.

**Плеер:** play/pause; next/prev — переход по очереди с зацикливанием, позиция сбрасывается на 0; клик по треку в любом списке — начать его и подсветить строку; seek — клик по полосе прогресса (доля от ширины). В макете прогресс идёт по таймеру 900 мс (демо) — заменить на `timeupdate` от `<audio>`. Индикатор уровня и волна анимированы; при паузе уровень падает до минимума.

**Анимации:** `pv-blink` — `0%,45% {opacity:1} 50%,100% {opacity:.15}`, применяется к статус-точкам (1.6–1.8s infinite; 0.7s при подключении). `pv-rise` — `from {translateY(8px); opacity:0} to {translateY(0); opacity:1}`, применяется к карточкам каталога (.3s ease) и полноэкранному плееру (.25s ease). Hover: кнопка-акцент → `#F0563A`; обводка → `border-color: #4A4A50`, `color: #E8E6E1`; строка списка → `background: rgba(255,255,255,.03)`; карточка → `opacity: .82`; текст-ссылка → `#E8E6E1`.

**Плотность:** тумблер `ВОЗДУШНО / ПЛОТНО` меняет вертикальные паддинги (контент `34px 44px 46px` → `20px 26px 30px`, строки списков `12px` → `8px`, строки узлов `17px` → `12px`, пункты сайдбара `11px` → `8px`) и размер карточек каталога (`minmax(194px)`/gap 26px → `minmax(150px)`/gap 16px). В приложении — настройка, а не кнопка в шапке.

**Состояния, которых в макете нет и которые нужны в приложении:** скелетоны загрузки каталога/треклиста, ошибка запроса к узлу (узел отвалился во время сессии → вернуть чип узла в предупреждающее состояние), прогресс загрузки трека в фонотеку, обновление токена и повторный логин при 401, оффлайн-режим (доступна только Library).

**Адаптивность окна:** окно ресайзится свободно. Строки узлов, шапки экранов, герой плеера и сетка карточек уже переносятся; проверить на 1280×720 (минимальная ширина окна — разумно 1100) и на 4K. Фиксированные значения — только сайдбар 216px и плеер 76px.

## Поиск по нескольким узлам

Фича приложения, которой в макете нет (макет фиксирует «поиск идёт только по текущему узлу»): fan-out-поиск по всем добавленным узлам силами клиента, без изменений бэкенда.

**Как включить:** на Каталоге, под поиском, — переключатель «По всем моим узлам»; виден, когда добавлено два и больше узлов. Режим opt-in — по умолчанию поиск идёт только по текущему узлу, — но выбор запоминается вместе с остальными настройками. Во включённом состоянии заголовок поиска меняется на «Поиск по узлам», запрос уходит на все узлы параллельно (потолок ожидания — 5 с), выдача склеивается в порядке узлов (активный — первым), а у строк артистов и треков стоит чип узла-источника (`open.eu3`, `independent`).

**Статус узла** — строка под поиском, когда узел не дал ответа: `не отвечает` — узел недоступен или не ответил за 5 с; `нужен вход` — сессии на узле нет или она истекла; `ошибка` — остальное, с текстом причины. Остальные узлы при этом ищут как обычно, на экран входа клиент не уводит.

**Полка остаётся полкой активного узла:** мультинодовый режим меняет только поиск. Полка каталога, локальная фонотека и очередь не трогаются; релиз или артист из сводной выдачи открываются на своём узле (`?host=`).

## State Management

Состояние макета (для переноса в Zustand/контексты):

- **Auth:** `authed`, `mode: 'login'|'register'`, `login`, `pass`, `birth`, `err`. В приложении — токены по узлам: `Map<host, {access, refresh}>`, в keychain через Rust-команды, не в localStorage.
- **Серверы:** `servers: Server[]` (id, name, host, owner, releases, ping, status, mode, note), `serverId` — активный узел, `newHost` — поле добавления, `srvErr`, `connecting` — id узла в процессе подключения. Список узлов персистится локально (файл настроек/SQLite).
- **Навигация:** `screen: 'servers'|'catalog'|'album'|'artist'|'library'`, `albumIdx`, `artistName` → в приложении роутер (`/servers`, `/catalog`, `/album/:id`, `/artist/:id`, `/library`).
- **Каталог:** `query`, `filter`. Кэш данных — по ключу `[host, resource]`, чтобы данные разных узлов не смешивались (TanStack Query подходит).
- **Плеер:** `playing`, `idx` (позиция в очереди), `pos` (процент), очередь. Персистить трек и позицию между запусками.
- **Вид:** `dense` (плотность) — в настройки; `view: 'desktop'|'mobile'` — выбросить.

**Данные, которые клиент запрашивает у узла:** дескриптор узла (имя, владелец, тип доступа, версия API), каталог релизов, треклист релиза, поиск, стрим трека (range-запросы), обложки, пики волны. Формат задаёт заказчик — макет подразумевает, что индексирует узел, а не клиент.

## Что не переносить в приложение

- **Переключатель DESKTOP / MOBILE** в шапке и весь мобильный вид (рамка 390×800 с таб-баром) — это витрина макета. Мобильный вид оставлен как референс на будущее (там же: мобильный экран узлов с добавлением по адресу, мини-плеер, таб-бар `ПОЛКА / УЗЛЫ / ФОНОТЕКА / Я`), но десктопное приложение его не содержит.
- **Тумблер плотности** в шапке — перенести в настройки.
- **Демо-таймер прогресса** (900 мс) — заменить на события `<audio>`.
- **Мок-данные** (`ALBUMS`, `TRACKS`, `SERVERS`, `SRV_OF`) — за слой API-клиента с тем же интерфейсом, чтобы UI не менялся при подключении реального узла.
- **Детерминированные высоты волны и уровня** — на реальные пики / анализ аудио.
